# 딜플로우 — 1단계 (소싱·실사 착수)

신규 딜 1건의 입력 엑셀과 자료 폴더만 채우면, 딜 초기 단계 산출물을 한 번에 만드는 프로그램입니다. 단계별 계획(1~13단계)은 [ROADMAP.md](ROADMAP.md)를 보세요.

## 1. 만드는 것

| 메뉴 | 입력 | 산출물 (`<딜폴더>/02_산출물/1단계/`) |
|---|---|---|
| 협의용 재무모델 | 재무가정·렌트롤 시트 | `재무모델/…협의용_v01.xlsx` — 수식이 살아 있는 모델(가정 → 렌트롤 → 임대수입 → CF → 요약). **실사반영** 열을 채우면 `…실사반영_v02.xlsx`와 직전 대비 변동 비교 메모를 함께 만듦 |
| Teaser | 자산개요·사진·렌트롤·일정 | `Teaser/…pptx` 4장(투자개요·자산시설·임대현황·거래일정), KLI v5.8 서식·최소 10pt |
| 실사 RFP 5종 | 자산개요·일정·실사업체 | `RFP/…시장·재무·물리·감정·법률 docx` + 후보 업체별 **발송용 임시 메일**(.eml, RFP 첨부) |
| 실사업체 선정 보고·기안 | 실사업체 시트의 견적·`선정(O)` | 선정 현황 장표(PPT 1장), 기안문(Word), 전자결재 붙여넣기용 본문(.txt), 선정·미선정 통보 메일(.eml) |
| 사업일정·체크리스트·캘린더 | 사업일정 시트(거래종결일만 넣어도 됨) | 체크리스트 엑셀(일정표·체크리스트·주차별), **캘린더 등록 파일(.ics)** |
| WGL·주소록 | WGL 시트 | WGL 엑셀(기관별, 메일주소 묶음), **주소록 HTML**(검색 → 이름 클릭 시 연락처 팝업, 체크한 사람 메일 주소 한 번에 복사) |
| 메일 이슈로그 | `01_입력자료/메일/`의 .eml·.msg | 기관별 자동 분류, 일자별 이슈·요청·기한 기록(엑셀·md). 다시 실행하면 새 메일만 누적 |

사업일정의 빈 날짜는 **안양물류센터 실제 일정 간격**(거래종결 기준 D-day)으로 채우고 `[추정]`으로 표시합니다. 체크리스트 항목은 `templates/milestones.json`에서 고칠 수 있습니다.

## 2. 처음 실행 (회사 PC, Windows)

1. 이 폴더를 통째로 원하는 위치에 둡니다(예: `D:\딜플로우`).
2. `run_dealflow.bat`을 더블클릭합니다. 처음 한 번은 패키지를 설치합니다(1~2분). Python 3.11~3.13이 필요합니다(RFIS 자동입력과 같음).
3. 메뉴에서 **1. 새 딜 만들기** → 딜 이름 입력 → `deals\<딜 이름>\` 폴더가 생깁니다.
4. `딜입력.xlsx`를 채웁니다(노란 칸 = 입력, 초록 칸 = 자동추출).
5. 자료를 넣습니다.
   - `01_입력자료\사진\` 사진(파일명 순서대로 첫 장이 대표 사진)
   - `01_입력자료\대장_등기\` 토지대장·건축물대장·등기부 PDF(파일명에 '토지대장', '건축물대장', '등기' 포함)
   - `01_입력자료\메일\` WGL 메일 — 아웃룩에서 메일을 이 폴더로 끌어다 놓으면 됩니다
6. 메뉴 **2. 1단계 전체 실행** → 산출 폴더가 자동으로 열립니다. `00_실행결과.md`에 요약과 "확인 필요" 목록이 있습니다.

예시: 메뉴에서 딜을 고를 때 `안양물류센터 (예시)`를 선택하면 안양 실제 자료로 만든 예시 딜이 실행됩니다.

## 3. 자주 쓰는 방법

- **캘린더 등록**: 구글 캘린더 → 설정 → 가져오기 → `.ics` 선택 → 딜 전용 캘린더(예: "딜-안양")를 고릅니다. 일정이 바뀌면 그 캘린더를 비우고 새 `.ics`를 다시 가져오세요. 아웃룩은 `.ics`를 더블클릭하면 됩니다. 알림은 전날 오전 9시입니다.
- **주소록 팝업**: `WGL\<자산명>_WGL주소록.html`을 즐겨찾기에 두세요. 항상 최신 파일 이름이 같습니다. 검색창에 기관·이름·역할 일부를 치고 이름을 누르면 연락처가 뜹니다. 데이터가 파일 안에 들어 있으므로 외부로 보내지 마세요.
- **임시 메일(.eml)**: 더블클릭하면 아웃룩 새 메일 창으로 열립니다. 내용을 확인하고 보내세요(자동 발송하지 않음).
- **실사 결과 반영**: `딜입력.xlsx` → 재무가정 시트의 **실사반영** 열에 값, **출처·비고** 열에 보고서명·페이지를 적고 메뉴 9 실행 → 새 버전 모델과 `검토메모_…변동비교.md`.
- **스캔본 대장·등기부**: 글자층이 없는 스캔 PDF는 자동추출이 안 됩니다. 입력값에 직접 적거나, `settings.txt`에 `USE_CLAUDE=1`과 `ANTHROPIC_API_KEY=`를 넣으면 Claude가 읽습니다. 이 경우 문서가 Anthropic API로 전송되므로 회사 정책을 먼저 확인하세요. 판독값은 `[원본 대조 필요]`입니다.

## 4. 유의사항

- 모든 수치는 협의·실사 전 **[추정]**입니다. 수익률은 목표·추정치이며 보장 표현을 쓰지 않습니다.
- RFP·기안문의 법률·세무 문구는 내부 검토 초안입니다. 외부 법무법인·회계법인 확인이 필요합니다.
- 기존 산출물은 덮어쓰지 않고 `v02, v03…`로 새로 만듭니다. 입력 원본(대장·등기부·메일)은 수정하지 않습니다.
- `deals\` 폴더·`settings.txt`는 깃에 올라가지 않습니다(`.gitignore`).
- 협의용 재무모델의 단순화: 대출은 만기일시·이자만 지급, 임차인별 최초 만기 1회만 시장임대료로 갱신(공실기간 적용), 고정비 정액, 법인세·감가상각·배당가능이익 제약과 종류주 트랜치·Overfunding은 미반영(3단계에서 고도화). 안양 예시는 기준 재무모델(v05) 대비 IRR이 낮게 나오는데, 이 단순화 때문입니다.

## 5. 파일 구조

```
platform/dealflow/
  run_dealflow.bat        실행(Windows)
  dealflow.py             메뉴·명령 (python dealflow.py run <딜폴더>)
  lib/                    inputbook(딜입력.xlsx) · deal(통합·deal.json) · docparse(대장·등기 추출)
                          finmodel · teaser · rfp · vendor · schedule · wgl · maillog · eml · docx_util
  templates/              milestones.json(일정·체크리스트) · rfp_scopes.json(RFP 범위) · holidays_kr.json
  samples/                build_sample_anyang.py → 안양물류센터 예시 딜
  vendor/                 (배포본에만) kli_deck.py · KLI_빈템플릿_v5.8.pptx
  deals/                  내 딜 폴더(깃 제외)
```

명령줄: `python dealflow.py new <폴더>` · `run <폴더>` · `teaser|rfp|vendor|schedule|wgl|mail|model <폴더>`
