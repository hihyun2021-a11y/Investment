# 딜플로우 단계별 로드맵 (1~13단계)

2026-11-05 운용역 지시. 안양물류센터(ANYANG-LOGIS) 진행 경험을 바탕으로, 딜 진행 단계마다 프로그램을 하나씩 만든다. 뒷 단계는 앞 단계 파일을 누적해서 쓴다. 최종 목표는 **신규 딜 폴더 하나만 올리면 전 공정이 순서대로 돌아가는 것**이다.

## 누적 구조 (모든 단계 공통)

```
<딜폴더>/딜입력.xlsx          1단계 입력. 뒷 단계는 시트를 추가해 확장(기존 시트 구조는 유지)
<딜폴더>/01_입력자료/…        사진·대장·등기·메일·실사보고서·계약서 원본 (원본은 수정하지 않음)
<딜폴더>/02_산출물/N단계/…    단계별 산출물 (날짜_유형_제목_v##, 기존 파일 덮어쓰기 없음)
<딜폴더>/deal.json            통합 데이터. 각 단계가 읽고 자기 결과를 덧붙임 ← 뒷 단계의 입력
```

`deal.json`에 쌓이는 주요 키: `asset`(자산개요) · `schedule`(마일스톤·체크리스트) · `wgl`(참여기관 명단) · `vendors`(실사업체) · `assume`/`assume_dd`(협의안·실사반영 가정) · `rentroll`/`rr` · `model`(재무모델 결과) · `mail_log`(메일 이슈) · `history`(실행 이력)

## 기존 자산 재사용
- PPT 서식: `platform/scripts/kli_deck.py` (KLI v5.8, 최소 10pt)
- 샘플 양식: 안양 RFP(`06_사내보고/RFP`), 기안문(`05_대출업무/약정서/build_기안문_*`), 추진일정 xlsm, 대주 통지처 엑셀, 사내 A&R 재무모델 양식(`platform/templates/financial_model`)
- 신규투자 워크벤치(`platform/webapp`): Claude API로 샘플 양식 기반 문서 생성 — 5단계 계약서·4단계 IM 문안 생성에 연결 예정
- 자금모집 메일 양식(`platform/standards/email_fundraising.md`) — 4·6단계 투자자 메일

## 1단계에서 미뤄 둔 것
- **전자결재 자동 상신**: 사내 결재 시스템 화면 정보가 없어 지금은 기안문 Word와 붙여넣기용 본문(.txt)까지 만든다. 결재 화면을 공유받으면 RFIS 자동입력처럼 브라우저 자동화로 상신까지 붙일 수 있다.
- **캘린더 직접 등록**: 지금은 .ics 가져오기. 구글 캘린더 API 연결은 회사 보안 정책 확인 후.
- **메일 자동 수집**: 지금은 메일을 폴더에 끌어다 놓는 방식. 아웃룩 폴더 직접 읽기(일일 보고 프로그램의 Outlook 연동 방식)는 2단계와 함께 붙인다.
- 재무모델은 단일 Equity·이자만 지급 대출의 협의용이다. 종류주 트랜치·리파이낸싱·Overfunding·배당가능이익은 3단계에서 고도화한다.
